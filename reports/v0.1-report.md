# FaithfulAgent v0.1 — Completion Report

_Generated 2026-03-15_

---

## 1. Executive Summary

FaithfulAgent v0.1 is a Python SDK that detects reference hallucinations in LLM agent outputs — specifically, cases where an agent misquotes, distorts, or fabricates values that should have come from a tool call. The verifier takes tool call logs and the agent's final text, decomposes the text into typed claims (numeric, string, currency, date), matches each claim to the tool-call field it should reflect, and runs deterministic checks to produce a machine-readable JSON report with per-claim pass/warning/error status. No LLM is involved in the verification path.

---

## 2. Scope Delivered

### What v0.1 Detects

One specific failure mode: the agent called a tool, got correct data back, then wrote something different. v0.1 does not check cross-claim consistency or logical relationships between claims — those are v0.2+ problems.

### Operating Modes

| Mode | Input | Matching | Coverage |
|---|---|---|---|
| **Strict** | Agent output is annotated JSON with a `refs` array linking each value to a `call_id` and JSONPath | Exact, via `call_id` + JSONPath resolution | Complete for all annotated fields |
| **Heuristic** | Agent output is plain text | Regex extraction (always runs) + spaCy NER (optional — when spaCy is installed, NER-based entity extraction is added as a second layer; if not installed, falls back to regex-only with a warning; installing spaCy via `pip install faithfulagent[heuristic]` is recommended for better extraction quality); closest-value matching; tie-breaking by list position (timestamp-based tie-breaking is supported in the schema but not yet used by the v0.1 matcher implementation) | Best-effort; matched claims set to `match_confidence: "medium"` (flat, regardless of match quality — see note in §4); unmatched claims set to `"low"` |

### Input Formats

| Format | Normalizer |
|---|---|
| Raw JSON | `normalizers/raw.py` |
| OpenAI function calling | `normalizers/openai.py` |
| LangChain `AgentAction` / `ToolMessage` | `normalizers/langchain.py` |

### Check Types

| Check | Claim Types | Logic |
|---|---|---|
| Numeric | `numeric` | `math.isclose`-style tolerance; rounding detection via `max_rounding_deviation` |
| String | `string`, `date` | Exact → case-insensitive → substring containment (post-v0.1 patch, not in original PRD) → fuzzy (`rapidfuzz.fuzz.ratio`) |
| Currency | `currency` | Numeric check + currency symbol/code comparison via static symbol map |
| Unit conversion | `numeric` | Ratio against static conversion table (km/mi, kg/lb, m/ft — both directions) |
| Derived value | `numeric` | Sum, average, min, max of all numeric fields in a tool response |

### Out of Scope for v0.1

- Cross-claim numeric and ranking consistency (v0.2)
- Dependency graph validation (v0.3)
- RAG source verification (v0.4)
- Causal reasoning verification (v2.0)

## 3. Architecture

### Pipeline

```
tool_call_logs ──┐
                 ├──→ Normalizer → Parser → Comparator → Reporter → JSON Report
agent_output  ───┘
```

Each stage produces typed outputs consumed by the next. No stage calls an LLM.

### Dependency Flow

```
schemas ← normalizers ← parsers ← comparator ← reporter
```

All modules import types from `schemas.py`. No module imports from a module to its right in this chain.

### Module Inventory

| Module | Description |
|---|---|
| `faithfulagent/__init__.py` | Public `verify()` entry point; re-exports all schema classes |
| `faithfulagent/schemas.py` | Pydantic models: `TextSpan`, `SourceRef`, `ToolCall`, `Claim`, `MatchResult`, `ReportSummary`, `Report` |
| `faithfulagent/config.py` | Per-check config: `NumericCheckConfig`, `StringCheckConfig`, `UnitCheckConfig`, `DerivedCheckConfig`, `VerifyConfig` |
| `faithfulagent/normalizers/__init__.py` | Dispatcher: routes `"raw"`, `"openai"`, `"langchain"` to the appropriate normalizer |
| `faithfulagent/normalizers/raw.py` | Validates raw JSON dicts against `ToolCall` schema |
| `faithfulagent/normalizers/openai.py` | Maps OpenAI function-calling format to `ToolCall` |
| `faithfulagent/normalizers/langchain.py` | Maps LangChain `AgentAction`/`ToolMessage` format to `ToolCall` |
| `faithfulagent/parsers/__init__.py` | Dispatcher: routes `"strict"` or `"heuristic"` to the appropriate parser |

## 4. Public API

### `verify()` Signature

```python
from faithfulagent import verify

report = verify(
    agent_output="The flight costs ¥553 and takes about 4.5 hours.",
    tool_calls=[{
        "call_id": "call_0a3f",
        "tool_name": "get_flights",
        "response": {"price": 553, "currency": "CNY", "duration_min": 270}
    }],
    mode="heuristic",           # "strict" or "heuristic"
    source_format="raw",        # "raw", "openai", or "langchain"
    checks={
        "numeric": {"tolerance": 0.05, "allow_rounding": True, "max_rounding_deviation": 10},
        "string":  {"case_sensitive": False, "fuzzy_threshold": 0.85},
        "unit":    {"allow_conversion": True},
        "derived": {"tolerance": 0.01}
    }
)
```

All `checks` parameters are optional and merge with defaults. `verify()` returns a `Report` object.

### Report Schema

```python
Report(
    verification_id: str,          # UUID4, auto-generated
    timestamp: datetime,           # UTC, auto-generated
    mode: "strict" | "heuristic",
    summary: ReportSummary(
        total_claims: int,
        passed: int,
        warnings: int,
        errors: int,
        verdict: "pass" | "warn" | "fail"
    ),
    claims: list[MatchResult]
)
```

**Verdict logic:** any `status="error"` → `"fail"`; any `status="warning"` with no errors → `"warn"`; all pass → `"pass"`.

Each `MatchResult` carries: `claim_id`, `matched_call_id`, `matched_field` (JSONPath), `expected_value`, `observed_value`, `status`, `mismatch_category`, `severity`, `match_confidence`, `diff`, and an optional `recommended_action`. Use `report.model_dump_json(indent=2)` or `to_json(report)` to serialize.

**Note — `match_confidence` deviation from PRD:** The PRD specifies that heuristic matches below confidence thresholds should be flagged as `"low"`. The v0.1 implementation does not do this. The actual assignment logic in `comparator/__init__.py` is binary: `"high"` when `claim.source_ref` is set (strict mode), `"medium"` for all heuristic matched claims regardless of match quality or score, and `"low"` only when no match is found at all (unmatched claim). Finer-grained confidence scoring based on match quality is deferred to a future version.

## 6. Known Limitations

**CI/CD:** There is no CI pipeline. Tests run locally only. Configuring a CI matrix is deferred post-v0.1.

**spaCy model download:** `en_core_web_sm` must be downloaded manually (`python -m spacy download en_core_web_sm`) and is not bundled. The error message on failure is informative, but the friction exists.

**Heuristic mode coverage gap in CI:** `tests/test_parsers/test_heuristic.py` uses `pytest.importorskip("spacy")` and skips the entire file when spaCy is not installed. A single CI environment with `pip install faithfulagent[heuristic]` and the model download is needed to cover this file. Without that, the effective coverage in a bare CI run would drop to approximately 93% (still above the 90% floor).

**No microservice wrapper:** The `verify()` SDK function is the only interface. A FastAPI wrapper is planned but deferred; the Pydantic models make it straightforward to add later.

**No evaluation benchmark:** The PRD targets 50–100 labeled traces for measuring precision/recall. This dataset does not exist yet. Accuracy claims for heuristic mode are untested against real agent outputs.

**Heuristic tie-breaking is list-order only:** The heuristic matcher breaks ties using input list position (later index = more recent). `ToolCall.timestamp` is stored in the schema but is not read by the matcher. Timestamp-aware tie-breaking is unimplemented.

## 7. What's Next (v0.2 Roadmap Preview)

### v0.2 — Numeric & Ranking Consistency Engine

v0.1 checks each claim against the tool data that produced it. v0.2 checks claims against *each other*:

- **Numerical consistency:** If the agent claims "Hotel A costs $200/night" and later "Hotel B is the cheapest at $150/night", both claims may pass v0.1 independently but contradict each other. v0.2 detects these cross-claim contradictions.
- **Ranking/comparison consistency:** If the agent asserts "A is cheaper than B" but the extracted prices show A > B, v0.2 flags the ranking claim as violated.

This requires building a claim graph structure and running constraint checks over pairs of claims — a non-trivial extension to the comparator.
